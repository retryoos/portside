LaytimelyHow the agents work together05

The pipeline, end to end

Four specialised agents. One pipeline. Every figure cited to its source.

Agent 1
Read
Extracts the Charter Party, the Notice of Readiness, and the hour-by-hour port log into a clean structured timeline.
→
Agent 2
Calculate
Works out the laytime. The arithmetic runs in plain Python, not in the model, so the numbers are exact and reproducible.
→
Agent 3
Argue
Finds the hours the other side will dispute and builds the legal argument with clause and event citations.
→
Agent 4
Draft
Writes the finished claim letter in the standard industry format, ready to send or to be reviewed by a lawyer.

This is the architecture we replicate for every new workflow. Each agent has one job. Each handoff is structured data, not free text. LLM for judgement, Python for money. That separation is why the output holds up in a dispute.

LaytimelyWhy you can trust the output06

The trust architecture

Numbers a court can audit. Arguments a counterparty cannot dismiss.

Every figure citedto its CP clause and SoF event id
Each line in the claim letter references the contract clause and the port-log event it came from. A reviewer or a lawyer can audit any number in seconds, without re-running the calculation.
Deterministic mathPython sums hours, not the model
The hours are summed by a plain Python function that is locked by an automated test. The number on screen is reproducible and identical between runs. No LLM hallucination is possible on the figures themselves.
Time bar trackedon every claim, from day one
The 90-day demurrage deadline is surfaced on every voyage so a valid case never expires on a forgotten calendar. We refuse to ship a feature that quietly drops a citation or a deadline.
Reviewable, editableyour team stays in the loop
Every claim letter is editable in the browser. Highlight a sentence, refine it with AI, or rewrite by hand. Export to PDF, Word, or Excel. Send via email. The audit trail follows.
